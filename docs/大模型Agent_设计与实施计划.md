# 大模型数据治理 Agent：设计与实施计划

> 本文记录最初只支持默认规则的改造阶段。可调规则的现行设计见 `docs/superpowers/specs/2026-09-25-configurable-agent-rules-design.md`；运行与验收以 `docs/迭代一_手动测试.md` 为准。

## 目标与边界

迭代一仍只执行完整 MovieLens 1M 数据和 `quality-clean-v1.0.0`。自然语言理解、工具选择和报告追问改由真实大模型完成；数据清洗、五维评分和报告数字仍来自 Hadoop。模型不能更改规则、直接生成评分或把未执行的任务说成已完成。

采用 OpenAI Responses API 的函数调用，模型与密钥由环境变量配置。未配置或模型服务失败时，新任务和追问明确失败；历史报告浏览保持可用。当前工作区没有 API 密钥，测试使用本地模拟响应，不把模拟结果作为真实模型验收。

## 数据流

1. 前端提交请求；服务调用模型，提供唯一的 `run_hadoop_clean_and_score` 函数工具。模型选择调用才创建任务，工具参数只能是已登记规则版本。对筛选、自定义规则或无关请求，返回拒绝原因。
   服务还会独立做保守的请求范围校验；即使模型误选工具，包含未登记限定词的请求也不会静默运行完整数据。该校验可能拒绝少见但有效的说法，用户可改用文档中的默认任务描述。
2. 服务保存模型决策的响应 ID 和模型名，异步运行原有 Hadoop 流水线。服务独立校验并发锁、任务状态和报告文件。
3. 已完成任务打开时，前端自动请求一次报告解读；用户也可继续追问。两者都要求模型先调用 `read_task_report`，服务从对应 `report.json` 读取完整报告，再把工具结果交给模型生成中文回答。回答显示报告路径和模型名。同一页面会话内自动解读按任务缓存，未完成任务不能追问。
4. 模型请求使用 `store: false`，密钥只从服务端环境读取。报告内容被当作数据，不能覆盖服务端指令。

## 实施顺序

1. 先写模型客户端与 Agent 的失败测试：密钥缺失、HTTP 错误、工具调用参数、拒绝请求、报告工具回传和最终回答。
2. 实现 Responses API 客户端与 Agent，删除关键词路由和模板问答。
3. 注入 Agent 到任务服务和 HTTP API；保存可核验的模型决策元数据；修改页面状态说明。
4. 更新手动测试文档与配置说明，运行单元测试、模拟 API 端到端测试和前端语法检查。

## 验收标准

- 不发生模型请求时不会新建任务；不发生报告工具调用时不会给出报告追问答案。
- 模型工具调用不能覆盖固定数据集和规则版本；失败与缺少密钥不能显示伪造结果。
- 模拟 Responses API 可验证真实 HTTP 请求结构和两轮追问工具调用。真实云端调用需用户配置有效 API 密钥后手动验收。
