# 可调规则数据治理 Agent 设计

## 目标

同一个自然语言入口可直接执行已登记的 `quality-clean-v1.0.0`，也可在明确请求时调整有限、可验证的清洗和评分参数。Hadoop 仍负责实际清洗与五维计分；模型只选择工具并填写参数。没有执行成功前不展示结果。

## 可调范围

- `min_retained_rating`：1–5，默认 1。高于 1 时，低于该值但本身合法的评分按 `policy_rating_below_minimum` 单独隔离；报告必须说明这是用户指定的策略过滤，不是无效评分。
- `missing_title_year_policy`：`flag`（默认）或 `quarantine`。严格模式隔离电影标题缺少年份的原始行，并可能使引用该电影的评分按关联缺失隔离；报告显示级联影响。
- `table_weights`：评分、用户、电影三张表的非负整数权重，至少一个正数，默认各为 1。对 Accurate、Complete、Unique、Consistent 使用同一组权重计算清洗前后的总体分；Up-to-date 始终只评价评分表。不创建综合分。

其他数据集、字段口径、原始数据有效性定义、任意脚本或未登记的配置不由模型执行，明确拒绝。若用户提出超出范围的条件，不能忽略条件后执行默认规则。

## 数据流与版本

Agent 暴露两个严格工具：原版默认工具与受限参数工具。服务校验模型参数，合并原版配置，为每个任务保存不可变规则快照；相同配置得到相同派生版本，默认配置保留原版本号。任务 sidecar 保存模型响应、工具、具体参数和规则版本。Hadoop Streaming 四个作业都加载同一快照，运行结束报告保存快照 SHA-256、参数、数据版本、四个 Job ID 与原有证据。旧报告保持可读。

模型若未选择工具、参数非法、模型服务失败或请求限定无法被支持，服务不创建 Hadoop 任务。任务级锁保持原有单任务约束。页面展示本次参数及评分口径，报告解释和追问读取相应任务的正式报告。原始数据不修改，后续迭代按净表版本及 T1/T2 区分产物。

## 验证

测试默认和自定义工具选择、非法参数拒绝、规则快照与版本、Hadoop Reducer 对策略过滤及标题年份处置、加权评分前后口径一致、报告回写和历史兼容。用本地模型模拟接口完成服务联调，再在 WSL 上运行至少一组自定义规则的真实 Hadoop 任务；没有云端密钥时明确记录未验收真实模型选择。
