# 迭代二系统说明、算法与接口

## 1. 继承与新增

基线为仓库提交`313b3bf`，保留同事完成的逻辑回归、决策树、时间安全分类特征、分类 Agent 工具、分类前端和既有数据治理流程。新增代码集中在`service/preferences.py`、`service/preference_tools.py`、`service/static/preferences.{js,css}`，接入原有`app.py`、`chat.py`和`workflow.py`。

实验一是独立的编程智能体实验，其“模型决策—工具执行—观察—校验”思路与后续 Agent 一致；不将实验一三个编程题的代码作为电影分析模型。实验二提供净表、报告和时间边界；实验三使用这些已登记产物，新增三类分析。

分类选型已核对用户提供的《26Fall-008-分类1010+1014》：第24页列出Decision Tree与Logistic Regression，第14页区分训练、验证和测试。现有决策树采用scikit-learn的CART/Gini实现，不声称是课件示例中的ID3或C4.5。K-Means、DBSCAN、PCA和截断SVD为小组确认的新增选型；这份分类课件不用于证明聚类与降维课件的覆盖范围。

## 2. 数据与时间边界

正式运行复用本地已存在且完整可校验的Hadoop任务`20260923T144724Z-3509cc23`。读取该任务自己的`report.json`和`cleaned.tsv`，检查字节SHA-256、三表行数、引用关系及T1/T2，不用报告样例代替完整净表。

净表版本`clean-c91a5e196ca1af48c3da`，T1为`2000-12-01T23:59:59Z`，T2为`2000-12-28T23:59:59Z`。评分按`Timestamp<=T1`、`T1<Timestamp<=T2`、`Timestamp>T2`切分。任何报告、时间边界或实现版本不一致都会拒绝沿用旧画像模型。仓库另有`20260930T112146Z-b0d51382`报告，其净表哈希不同且本机缺少对应完整净表，不能将本轮净表复制到该任务下冒充相同版本。

分类沿用现有逻辑：训练评分的特征仅用严格更早的训练评分；同一时间戳批量构造特征后才更新历史。验证、测试及在线预测统一用T1冻结历史。验证F1优先、AUC次优选择超参数；方案确定后再评价测试集。

无监督分析只使用T1之前的评分构建画像与拟合缩放器、聚类器、降维模型。没有用验证/测试评分来选择无监督配置；预先指定的参数及各次实际结果全部记录。无监督内部指标不是测试集分类准确率。

## 3. 用户画像

每位用户57维：18种类型的历史评分涉及比例、18种类型的均分（除以5）、18种类型的高分比例，以及总体`log1p(评分次数)`、均分（除以5）、高分比例。类型涉及比例的分母为该用户所有已知类型涉及次数；多类型电影同时计入各类型。类型均分为0表示该类型没有可用历史。总体统计包含类型缺失的训练评分，类型统计忽略此类事件，报告记录其数量。

不把UserID、人口属性作为偏好特征。默认至少5条训练评分；不足者在`profiles.json`逐人记录状态和原因，不填充坐标或群体。数据集原始入选用户有至少20次评分，不代表其在T1时已经有20次评分，因此不能假定所有用户都有足够训练历史。

`StandardScaler(with_mean=False)`仅拟合符合门槛的训练用户画像，按各维标准差缩放。保留未中心化输入，便于比较PCA中心化方向与SVD未中心化方向。缩放器、原始画像、特征名、数据来源和截止时间均保存，可供迭代三复用。

## 4. 四种无监督算法

| 算法 | 选型依据 | 默认参数 |
| --- | --- | --- |
| K-Means | 固定群数基线，最小化群内平方距离，方便解释不同用户偏好 | n_clusters=4, n_init=10, random_state=42 |
| DBSCAN | 通过密度形成群体并标记噪声，比较固定群数假设的局限 | eps=3, min_samples=10, 欧氏距离 |
| PCA | 中心化后最大化保留方差，提供线性主方向和逆变换 | 目标2维，full SVD |
| 截断 SVD | 直接分解未中心化缩放画像，比较与PCA的方向差异 | 目标2维，randomized, n_iter=7, random_state=42 |

可修改`min_history/n_clusters/eps/min_samples/dimensions/retention`。若提供`retention`，按累计实际方差保留达到阈值选择维数，优先于`dimensions`；模型会按选定维数重新拟合并检查实际保留率。无法达到阈值时明确失败，不谎称满足。两种降维都保存模型、全部实际维度坐标、重建均方误差、方差保留及真实资源指标。

在原始画像、PCA表示、SVD表示上分别运行相同配置的两种聚类算法。记录轮廓系数、Calinski-Harabasz（CH）、Davies-Bouldin（DB）、噪声数量及比例；前后比较还记录ARI。噪声点不参加三项内部指标；轮廓系数固定种子42且最多抽样1000人。群体不足两个等情况下返回`null`和原因。ARI把-1噪声标签作为一类。

群体摘要包括人数、用户均分的平均值、用户高分比例的平均值、平均类型偏好、成员训练期高分次数最多的代表电影。噪声不等于异常用户；代表电影是统计描述，不是推荐。群体编号在不同模型间不可直接对应。

二维图始终显示前两个分量，一维结果的第二坐标为0。左图投影显示原始画像上的群体标签，右图显示降维后重新聚类的标签；如果实际压缩到更多维，聚类仍使用全部实际维度。图支持按K-Means/DBSCAN切换和SVG下载。

## 5. HTTP接口

所有路径的前缀为`/api/tasks/<task_id>/preferences`；任务ID必须指向已完成清洗任务。

| 方法 | 路径 | 输入与返回 |
| --- | --- | --- |
| POST | /train | `{}`使用默认参数，或参数对象；异步返回queued |
| GET | /status | 返回未开始、排队、执行阶段、已完成、中断或失败原因 |
| GET | /report | 当前已完成实验的版本、配置、群体摘要、对照指标与产物校验和；`?download=1`下载 |
| POST | /query | category为cluster或reduce；algorithm为登记算法；可选user_ids、parameters、comparison_algorithm |
| GET | /data/profiles.json | 全部实际画像与历史不足清单 |
| GET | /data/kmeans.json、dbscan.json | 用户群体与噪声标记 |
| GET | /data/pca.json、truncated_svd.json | 全维坐标及两种降维后聚类标签 |

查询示例：

```json
{"category":"reduce","algorithm":"pca","user_ids":[1,2216,999999],"comparison_algorithm":"kmeans"}
```

查询可指定最多200个不重复用户；空集合返回前30位可分析用户样例并显式标记`sample_only`。未知ID和历史不足逐人返回状态，不伪造群体或坐标。模型在全部合格训练用户上拟合，查询集合只是读取子集，不重新拟合。`parameters`可省略；指定时必须与当前已登记配置一致，改变配置必须先重新训练。降维可选`comparison_algorithm=kmeans/dbscan/both`，返回选定算法在原始和压缩空间的实际对照。HTTP请求体上限沿用16KB。

分类接口保留`classification/train/status/report/predict`，见`CLASSIFICATION_GUIDE.md`。

## 6. Agent工具与执行证据

| 工具 | 行为 |
| --- | --- |
| train_user_preferences | 根据明确请求异步构建画像及四种模型，参数对象需给出实际配置 |
| get_preferences_status | 查询实时执行阶段和失败原因 |
| read_preferences_report | 读取已完成报告，提供配置、版本和指标依据 |
| cluster_users_kmeans | 独立查询K-Means实际群体、摘要及评价 |
| cluster_users_dbscan | 独立查询DBSCAN实际群体、噪声及评价 |
| reduce_users_pca | 独立查询PCA坐标、信息保留、资源和原始/压缩后聚类对照 |
| reduce_users_truncated_svd | 独立查询截断SVD及聚类对照 |

保留`predict_high_rating_logistic_regression`和`predict_high_rating_decision_tree`，合计六种算法都有独立工具。未指定分类、聚类或降维算法时，Agent指令要求调用对应两种算法；指定则调用指定算法。先登记计划，再执行工具并评估原问题是否有足够证据。异步提交不是分析完成。缺失数据或模型时返回明确错误；查询错误会覆盖模型虚构的自然语言结论。工具输出与报告作为证据卡片保存在对话中，支持追问。

自然语言服务使用已有Responses兼容客户端。API Key仅在进程内存或用户环境变量中提供，不写入仓库、提交包或截图。本环境没有可用模型密钥；已通过模拟模型协议测试验证调度与边界，但没有真实云端模型端到端验收证据。面板与命令行的真实训练和推断不依赖大模型。

## 7. 版本产物与后续迭代

`runs/<task_id>/preferences/report.json`指向最后一次成功实验；每次运行保存独立的`pref-<配置与实现哈希>-<运行后缀>/`目录，包含`report.json`、14个登记文件及SHA-256。即使配置相同，也保留实际时间和模型文件的历史版本，不覆盖旧运行。发生失败不会发布半成品报告；原来成功的报告仍可查询，状态接口单独说明最近一次运行的失败。

分类保留两个joblib模型、冻结历史和历次报告。迭代三应从报告读取数据版本、T1/T2、模型/画像版本，然后关联同一净表的用户和电影；禁止仅按文件名猜测兼容性。

`scripts/verify_iteration2.py`重新校验净表、14份画像产物与两个分类模型，实际载入缩放/降维模型复算坐标、核对群体标签并执行分类推断。运行机器的库版本写在报告和`docs/运行环境.txt`，joblib跨版本移交优先保持相同库版本；不兼容时在相同净表与配置上重新训练。

## 8. 局限

两种降维只有二维时会丢失大部分方差；轮廓系数变高不能证明保留更多信息。不同空间的CH、DB、轮廓系数受距离几何影响，应连同保留率、ARI和噪声覆盖率解读。DBSCAN在不同维度使用相同eps是敏感性对照，不保证密度语义相同；不能把高噪声率或单大群体隐藏成好结果。

资源记录的是实际拟合/变换秒数、输入矩阵字节、坐标字节、模型文件字节，不等同于进程峰值内存。人口属性是用户自报数据；模型输出是对发生评分事件的估计，不是评分事实、因果结论或真实喜好的完整描述。
